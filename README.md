# chat-miner

Скилл для Claude Code: находит в экспорте Telegram-чата сообщения по заданной теме, отбирает среди них кейсы и пишет отчёт в Markdown.

Работает в три шага:

1. **Классификация через Jev.** Каждое длинное сообщение получает вопрос «подходит ли оно под цель» (ответ — вероятность «да» от 0 до 1). Jev — это Decisions API сервиса OpenRouter, модель `typesafe/jev-1.13`.
2. **Отбор кандидатов.** Сообщения, у которых вероятность достигла порога из спецификации, получают контекст: сообщение-родитель и по два сообщения до и после.
3. **Извлечение и отчёт.** Кандидаты читает языковая модель и записывает результат построчно в `extractions.jsonl`. Затем `report` собирает `report.md`: сводку, найденные кейсы со ссылками на посты, сомнительные случаи и расходы на Jev.

## Требования

- Python 3. Внешних библиотек не нужно.
- Ключ OpenRouter в переменной окружения `OPENROUTER_API_KEY`. Скрипт также читает её из файлов `.env.local` или `.env` в папке скилла. Оба файла игнорируются git и в репозиторий не попадают.

Ключ нельзя вставлять в чат, коммиты, отчёты и публичные issue. Если он попал в переписку, его нужно перевыпустить.

## Установка

```bash
git clone https://github.com/Asmadey/chat-miner.git ~/.claude/skills/chat-miner
```

## Использование

Рабочая папка создаётся вне любого git-репозитория, потому что в ней лежат тексты сообщений.

```bash
S=~/.claude/skills/chat-miner
W=~/chat-miner-runs/my-search

# 1. Подготовка: из экспорта Telegram (JSON) в messages.jsonl
python3 $S/scripts/mine.py prepare --export result.json --work "$W"

# 2. Классификация. Без --send скрипт только показывает план и стоимость
python3 $S/scripts/mine.py classify --work "$W" --spec specs/ai-automation-results.json
python3 $S/scripts/mine.py classify --work "$W" --spec specs/ai-automation-results.json --send

# 3. Кандидаты: сообщения, которые прошли порог спецификации
python3 $S/scripts/mine.py candidates --work "$W" --spec specs/ai-automation-results.json --threshold 0.6

# 4. Извлечение. Читает candidates.jsonl пачками по 20–40 и пишет extractions.jsonl
#    (этот шаг выполняет языковая модель по правилам из SKILL.md)

# 5. Отчёт
python3 $S/scripts/mine.py report --work "$W" --spec specs/ai-automation-results.json --export-name result.json
```

Порог из спецификации — это отправная точка. Перед тем как доверять ему, проверьте выборку вручную: команда `eval` сравнивает ответы с размеченными примерами.

## Спецификация

Спецификация — JSON-файл в папке `specs/`:

- `target` — описание того, что ищем;
- `questions` — вопросы для Jev с инструкциями и критериями;
- `gate` — порог и поле, по которому проходит отбор.

Если поменять вопросы, меняется хэш спецификации, и все сообщения спрашиваются и оплачиваются заново. Порог менять можно без пересчёта.

## Приватность

- В экспорте есть имена и ID участников. Не публикуйте файлы `result.json` и папку с результатами.
- Во внешние модели отправляется только текст с анонимизацией (`text_anon` из `candidates.jsonl`). Сырой текст остаётся локально.
- Ссылки вида `t.me/c/<chat_id>/<message_id>` работают только для участников приватного чата. Для публичных чатов ссылки не строятся.

## Состав

| Файл | Назначение |
|---|---|
| `SKILL.md` | Инструкция для Claude Code: шаги, правила извлечения, формат отчёта |
| `scripts/mine.py` | Основной скрипт: `prepare`, `classify`, `candidates`, `eval`, `usage`, `report` |
| `scripts/label.py` | Ручная разметка сообщений для проверки порога |
| `scripts/anonymize.py` | Анонимизация текста перед отправкой во внешнюю модель |
| `references/jev.md` | Описание API Jev: эндпоинт, формат запроса, типы вопросов |
| `specs/` | Спецификации поиска |
| `tests/test_mine.py` | Тесты (без обращения к сети) |

Запуск тестов:

```bash
python3 -m pytest tests/
```
